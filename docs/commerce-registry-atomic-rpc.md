# Atomic Commerce Registry RPC

## Boundary

0B3C3B adds `public.apply_commerce_registry_sync(jsonb)` for local validation only. The function accepts only `commerce-registry-apply/v1` and returns `commerce-registry-apply-result/v1`. It creates no remote data, executor, CLI, marketplace call or OAuth activity.

## Transaction and lock

One RPC call is one PostgreSQL transaction. Pure JSON structure, root, parent, path, leaf, classification and count invariants are validated before writes. The function then uses `pg_try_advisory_xact_lock(hashtextextended(...))` keyed by marketplace plus site, checks active seeds, and row-locks relevant current categories and mappings. Lock contention fails immediately with `REGISTRY_SYNC_LOCKED`; any exception rolls the entire call back.

The implementation uses repeated set-returning parsing through a private, non-executable helper. It creates no persistent or temporary staging relation, uses no dynamic SQL and performs no DELETE.

## Category facts

Natural identity is marketplace, site and external category ID. UUIDs are generated by the table default and reused on conflict. New nodes are inserted without parents, then parent UUIDs are resolved within the same marketplace/site. Desired facts update only under `IS DISTINCT FROM`; a new source version or factual/reactivation/parent change advances factual timestamps. `first_seen_at` never changes, and a semantic replay—even with a different `checkedAt`—does not churn timestamps. Absence from a vertical payload never inactivates the marketplace category fact.

## Vertical mappings

Missing desired mappings are inserted as active AUTO decisions. Existing inactive mappings are reactivated. AUTO commercial fields change only when their desired decision or classifier version changes. Manual mappings may be inactivated or reactivated, but scope, tier, family fields, rule/version, source, reason, decision timestamp and override flag remain protected. An active divergent manual mapping is counted as `manualOverrideSkipped`.

Only active mappings that belonged to the pre-existing controlled root and are absent from desired state are inactivated. No mapping is deleted. Effective counts are calculated from active mappings under the root after apply and may legitimately differ from desired counts because of manual overrides.

## Security

The RPC is `VOLATILE SECURITY DEFINER`, owned by `postgres`, pins an empty `search_path`, fully qualifies persistent objects and has no SQL dynamic execution. `PUBLIC`, `anon` and `authenticated` cannot execute it; only `service_role` can. Direct INSERT and UPDATE on `marketplace_categories` and `vertical_category_mappings` are revoked from `service_role`, while SELECT remains. DELETE remains denied and RLS/no-public-policy protections are unchanged. Seed-table grants are unchanged.

## Local verification

pgTAP covers function properties, grants, payload failures, first apply, replay, checkedAt-only replay, source/classifier drift, parent resolution, manual protection, inactivation/reactivation, UUID stability, accounting and rollback after a forced test-only DML failure. A two-session local smoke validates same-key lock rejection. Remote apply and the full 3,269-row TypeScript roundtrip remain explicitly outside this build.
